# DECISIONS

Dated record of every deviation from the spec and every verified fact from the ARCHITECTURE.md section 16 checklist. If a choice is not obvious from the spec, it is written down here.

## Process decisions

### 2026-08-19: marketing site stays out of the public tree
The product is the CLI, the library, and the published methodology. The marketing site is a separate publication. `website/` is gitignored the same way `wiki/` is, so the open-source repository does not carry HTML, CSS, or deploy notes for a site that is not the product. Files already on `main` are removed from the tree in the same change. They remain in git history until a history rewrite, which this change does not do.

### 2026-08-18: local git only, no remote yet
The repository is initialized locally on branch main. No GitHub repository, no package registration, no name reservation anywhere until the maintainer opens the project up.

### 2026-08-18: the builder handoff stays out of the public tree
The handoff notes are build-process instruction, not user documentation. They live in the internal wiki, which is excluded from git. ARCHITECTURE.md and README.md are the public documents.

### 2026-08-18: MIT licence with a neutral copyright line
LICENSE names "firstpass contributors" as the holder. Repository files carry no personal names, emails, or machine-local paths. The maintainer's GitHub handle can be added at launch.

### 2026-08-18: README maintainer contact reduced to a placeholder
The draft README carried a personal name and email address. Replaced with a placeholder pending launch, per the rule that repo files hold no personal information beyond a GitHub username.

### 2026-08-18: Python 3.11 floor, developed on 3.12
The handoff requires 3.11+. The build machine runs 3.12; CI should exercise 3.11, 3.12, and 3.13.

### 2026-08-18: weekend 1 live success test deferred until a key exists
No Companies House API key is available in the build environment, and key registration requires an account only the maintainer can create. All code and tests run on recorded, fictional fixtures. The "real memo for a real UK company" test runs the moment a key is provided; nothing in the design depends on waiting.

## Build decisions

### 2026-08-18: weekend 1 built, adversarially reviewed, fixed, and verified
The deterministic core was implemented by a builder agent against a versioned work order, then reviewed by an independent agent with a fresh context. The review confirmed every quality gate independently and produced 20 findings; 17 were accepted and fixed, 2 were false positives (adjudicated against the primary documents), and 1 concerned a working tree edit made by the orchestrator, not the builder. The one substantive bug: pagination advanced by the requested page size rather than the received count, which would have silently skipped records if the server ever clamps page sizes (the maxima are officially undocumented). Fixed, with a regression test simulating a clamping server. Final state verified independently: 135 tests green on Python 3.11, 3.12, and 3.13, ruff and mypy clean, language check clean, zero network in tests, offline rerun demo byte-stable.

Decisions made during the fix pass, with reasons:
- The disambiguation exit code is 3, not 2, because typer and click reserve 2 for usage errors and scripts must be able to tell the cases apart.
- A unique exact-title match proceeds without a picker, but the choice is surfaced on stderr with the number of candidates set aside. A unique match on the exact registered name is determinate rather than ambiguous; the notice keeps the spec's "ambiguity is surfaced" principle intact.
- The PSC fetch is gated on the profile's PSC link, mirroring charges and insolvency, because unlinked PSC resources can 404. An absent link produces an absence finding with confidence "indicated" (the register offered no link), while a fetched empty register stays "confirmed".
- Non-200 responses on linked or list resources are persisted as evidence files with their status codes, so the audit pack shows, for example, the insolvency 404 itself. Terminal errors that abort a screen write no case directory, so they have no audit pack to appear in.
- The test clock seam (FIRSTPASS_SCREENED_AT) is now visible: the casefile carries a clock_override flag and the memo footer states when timestamps were injected. An audit pack cannot be silently backdated with one environment variable.
- The fixture company number moved from 09999999 to 99999999 because the former falls in an allocated Companies House range and could be pasted against the live API.
- uv.lock is not tracked. This is a distributable package, CI installs from pyproject, and the lockfile would only add churn.

### 2026-08-18: weekend 2 pre-build verification (FtM properties, disqualification schemas)
FollowTheMoney property names for OpenSanctions match queries verified from the canonical schema YAML: Person queries use name/firstName/lastName/birthDate/nationality (partial birth dates like "1951" officially accepted); Company queries use name/jurisdiction/registrationNumber/incorporationDate. Properties not belonging to the queried schema are silently dropped, so people are queried as Person and the subject as Company, never as a generic LegalEntity. Companies House disqualified-officers schemas verified: search items carry the name as one unstructured title string and a scalar date_of_birth (unlike the officers list's month/year object); the natural detail resource has structured forename/surname and disqualifications with disqualified_from/disqualified_until. Design consequence: a disqualification only becomes a red R3 candidate when the name matches strongly (normalized name plus DOB month and year) AND the disqualification is currently active (disqualified_until on or after the screening date); expired or name-only matches are informational. Sources: followthemoney.tech, github.com/opensanctions/followthemoney schema YAML, opensanctions.org/docs, developer-specs.company-information.service.gov.uk, retrieved 2026-08-18.

### 2026-08-19: weekend 2 built, adversarially reviewed, fixed, and verified
The judgment layer (network expansion, sanctions and PEP screening, adverse media, synthesis with the rubric) was built by a builder agent, reviewed by an independent fresh-context agent, and fixed by a third agent against the accepted findings. Final state verified independently: 316 tests green on Python 3.11, 3.12, and 3.13 with the dead-proxy property intact, ruff and mypy clean, language check clean.

Verdict enforcement is now a floor and a ceiling. Floor: mechanically detected trigger candidates (sanctions match, active insolvency, active strong-match disqualification, overdue filings, wholesale officer changes) cannot be omitted by the model. Ceiling: model-cited R1, R2, or R3 are accepted only when mechanically detected; R4 and R5 are rejected until the claims layer exists; A3 and A6 remain freely citable judgment triggers. The verdict level is a pure function of the enforced trigger set, so the rubric anchoring property holds by construction in both directions. Every enforcement intervention is recorded in the casefile and rendered in the memo using sanitized fixed text that never echoes model-controlled strings.

The language control has three layers: the prompt states the rules (advisory), the synthesis gate scans model output fields with one corrective retry (mechanical), and a whole-memo scan runs before any memo is written to disk (backstop). Decision: the banned-word scan strips URLs before matching, because source URLs are data pointers, not prose, and real adverse-media URLs legitimately contain words like fraud in their slugs; the memo's own prose remains fully gated. Decision: when synthesis fails its gate, the run ships the deterministic memo plus a sanitized failure note and exits 1, preserving the audit pack; in the double-failure corner where even the failure note would contain banned text, the run fails closed without writing the case directory, because the language guarantee outranks audit-pack preservation.

Local model verification with zero cloud keys, via the locally running Ollama. On the pre-fix build: a real synthesis smoke on qwen2.5:7b produced the correct enforced AMBER in 16.7 seconds while the enforcement layer visibly corrected three misbehaviors of the weak model, and the cross-model anchoring test passed across qwen2.5:7b and qwen3-coder:30b (identical AMBER level; the larger model added the A6 media judgment, which by design cannot move the level). On the final build: qwen3-coder:30b reproduces AMBER with A1, A2, A6 in 17.7 seconds; qwen2.5:7b now deterministically fails the language gate on the regenerated golden input (writes "criminal", the corrective retry does not clear it, the run fails closed), which we record as a model-viability floor rather than weakening the gate; gemma4:26b hangs on schema-constrained output and muse-glimmer:30b-mlx returns empty output under schema constraints, so neither is usable locally. The anchoring property on the final build is guaranteed by the enforcement design and proven by parametrized tests that hold the verdict level constant across five fabricated model behaviors per casefile; the empirical cross-model run on final bits awaits either a second viable local model or cloud keys. The Ollama context length is a config knob (default 16384) after the default context proved too small for synthesis input. Officer-and-PSC duplicate humans are screened once with both roles recorded, halving paid sanctions queries for owner-directors.

Still unproven until keys exist: live Companies House, live cloud providers, live OpenSanctions and Tavily, and the weekend 2 success test on live companies (coherent AMBER and GREEN verdicts on two real screens). The offline surrogates for that test are the golden AMBER and green GREEN snapshot cases.

### 2026-08-19: weekend 3 built, reviewed, hardened; the exemption laundering episode
The claims layer (deck extraction via pdfplumber, site extraction with robots.txt respect, model claims extraction, assessments with code-resolved basis evidence, the claims-vs-evidence table, and the R4/R5/A3/A4/A5 enforcement unlock) was built, adversarially reviewed, and fixed. Final state verified independently: 469 tests on Python 3.11, 3.12, and 3.13, dead-proxy property intact, golden RED case replaying byte-identically through the real CLI with the claims table.

The review found the sprint's one must-fix, and it was in the signature feature's safety control: the quoted-data exemption (which lets a company's own deck words like "we fight fraud" render in the claims table without tripping the banned-language gates) trusted model-supplied claim texts and applied them as whole-memo exemption spans. Four executed attack shapes landed banned vocabulary in rendered memos, including pure fabrications. The hardened design: model prose fields are gated with zero exemptions everywhere (prose references claims by id, never repeats their wording; synthesis prompt version 3); a claim text is stored only if it verifies as a normalized verbatim substring of its declared source section, with failures dropped and counted in a finding (never retried, so a model cannot iterate against the verifier); exemption spans advance by match length; and the language check script honors an exemption only when the claim text re-verifies against the committed evidence files, proven by a tamper test. All four attacks are permanent CLI-level regression tests.

Related decisions: the A4 trigger requires a model-authored unverified assessment (code back-filled rows keep the table complete but cannot open A4); A3 and A5 require at least one checkable claim, so slogan-only decks unlock nothing; the claims extraction prompt (version 2) extracts only what the company asserts about itself, treating market statistics and third-party facts as context rather than claims. Live verification on a real 21-page inbound deck with a local model: version 1 of the prompt yielded 20 claims including market noise; version 2 with quotation verification yielded 11 stored claims, all genuine company assertions, with 9 paraphrases dropped by the trust boundary. The retroactive demo target is CARILLION PLC, chosen empirically over the handoff's Wirecard suggestion after live-screening four candidates (richest registry signal: liquidation, insolvency case, six charges, seven officers); the demo framing is honest about being a post-collapse screen of the current record.

### 2026-08-19: hardening reviewed, SSRF rebinding hole found and closed
The hardening package was reviewed by an independent fresh-context agent with one question named as its priority: does the site fetcher connect to the address it validated, or does the HTTP client re-resolve the hostname at connect time. It re-resolved. The address-classification and redirect layers were flawless, but they validated a DNS resolution that httpx discarded and independently re-resolved when it dialed, so a subject controlling its own DNS with a short-lived record answering public-then-private (DNS rebinding) reached loopback, private, or cloud-metadata addresses after passing the check, and the internal response body was persisted as evidence and sent to the claims model. The reviewer proved it with a hermetic loopback-server harness.

Fix: the site client now dials only pinner-validated addresses. A single resolution is classified and pinned; a custom httpcore network backend substitutes that validated address as the TCP target while the HTTP layer keeps deriving the Host header and TLS SNI from the original hostname, so name-based virtual hosts and certificate validation are unaffected. The pre-check and the connection share one pinner instance, so the address checked is the address dialed. Environment proxy mounts are disabled on the site client (they would bypass the pin). The transport reaches into an httpx private attribute to install the backend, guarded to fail closed (refuse to run the site stage) if that internal shape ever changes, and covered by a real-socket rebinding test that would break loudly on drift. Verified independently: the hermetic test proves the system resolver never sees the attack hostname and the only dial target is the validated address; I read the implementation and the test rather than trusting the report, because this is a security boundary.

The same review confirmed the completed enforcement ceiling holds: every trigger id is gated (a model citing all twelve with no supporting evidence yields GREEN), and a property test bounds the verdict level between the candidate-only level and the candidates-plus-open-gates level across tens of thousands of random model outputs. Two smaller fixes folded in: status matching is casefolded so a mixed-case registry status cannot miss R2 or A7, and a mechanical stage-honesty backstop fails closed if a synthesis narrative describes a not-run or failed sanctions or media stage as clean (this immediately caught six existing tests that replayed a canned "sanctions returned no candidates" line against a company whose stages never ran, a true positive; those tests were corrected). Live confirmation on real registry data: liquidation and administration statuses fire R2 as mechanical candidates, active companies fire none. Deferred with reasons: the stage-honesty phrase set is fixed and narrow and will be extended from real model phrasing after live runs; TLS SNI preservation through the pinned backend is proven by design and by a plain-HTTP Host-header test but awaits a first live HTTPS fetch; the httpx-internals coupling is pinned to the tested versions and fails closed otherwise.

### 2026-08-19: mechanical origin-year R4 floor; rubric v0.3
R4 had a ceiling (a model cannot cite it without a surviving relevant contradiction) but no floor, so a claims-bearing case with "operating since 2015" against an incorporation date of 2019 anchored only if the model marked that claim contradicted. That is the most common contradiction class and the planted golden case. Rubric 0.3 adds the floor without opening a hole in the ceiling.

Detector: stored claim texts (verified quotations, including puffery) are scanned for origin-shaped date patterns at year granularity. Duration verbs (operating, trading, started) require since/from; event verbs (founded, established, incorporated, formed, launched, began) accept optional in/on; a leading "Since YYYY" on the claim counts. A negation in the forty-eight characters before a match suppresses it. Fire only when the parsed origin year is strictly before date_of_creation.year. Same-year claims ("Founded in 2018" against 2018-06-15) do not fire: a year-level claim can be true of any day in that year. Years outside 1800-2099 are ignored.

R4 stays a judgment-gated id so a non-date contradiction (debt-free against a charge) still has to clear the surviving-assessment gate. detect_candidates additionally emits R4 when the origin-year detector hits; enforce accepts a citation if the gate is open OR the candidate is present, and the floor adds the candidate when the model omits it. enforce_assessments forces a checkable origin-year hit to contradicted with REG-002 evidence; a surviving model contradiction with a non-empty basis keeps its language-gated record note. The code-written note names only the parsed year, the ISO incorporation date, and REG-002, never the claim wording.

Synthesis prompt bumped to version 5 so memos record which instruction set produced them. Snapshot fixtures regenerated through the real pipeline for the prompt-version footer. The golden casefile's red floor is now unconditional on the origin-year candidate plus A1 and A2. Official docs updated in the same change: ARCHITECTURE.md section 8 now points at the live rubric (including A7 and the R4 hybrid), README states the origin-year floor plus A6 and A7, the website rubric table matches 0.3. Internal wiki updated: log session 7, plan, launch candidates, work-orders/r4-origin-year.md. Public HANDOFF.md now states that official docs and the gitignored wiki both get updated when behavior changes.

### 2026-08-19: library pipeline extracted; MCP stdio server
The screen and rerun flows moved out of the Typer commands into `src/coldscreen/pipeline.py`, which returns structured results (`ScreenResult`, `RerunResult`, `CaseLoad`) and never exits the process, prints, or prompts. `cli.py` is now an adapter that loads settings, calls the pipeline, and maps results to exit codes and console output; `mcp_server.py` is a second adapter mapping the same results to structured tool content and `ToolError`. There is no second screen implementation, so the verdict floor and ceiling, the language backstop, and the evidence schema are literally the same code on both paths. CLI snapshots are byte-identical and the CLI test suite was not modified beyond two new tests for the new command.

Two tools, `screen_company` and `rerun_case`, stdio only, behind an optional `mcp` extra that is also pulled into `all` and `dev`. The `mcp` import lives inside the command handler, so a default install imports and runs with the extra absent and `coldscreen mcp` explains what to install (there is a test that loads a fresh `cli` module with every `mcp*` module evicted from `sys.modules`).

Decisions inside that shape, each of which could have gone the other way:

- **No key surface at all.** Neither tool schema has a field that could carry key material; keys come from the server process environment that the host sets. A test walks both input schemas and fails on any field whose name looks key-shaped, and another asserts a Companies House key present in the environment appears in neither the tool result nor anything written to disk. Passing keys as arguments would have been more convenient for hosts and is exactly the leak non-negotiable 5 forbids.
- **Ambiguity returns candidates.** The CLI can prompt a person; an MCP tool cannot, and a tool that picked the first match would let the model choose the company, which is a registry fact by another door. An ambiguous name returns `status: "ambiguous"` with the candidate list and writes nothing. Error and status messages are spelled per interface (`--overwrite` on the CLI, `overwrite=true` on the MCP path) through an `ArgumentNames` record passed into the pipeline, so neither surface tells a caller to use the other one's syntax.
- **The verdict in the payload is the enforced level**, read from the written casefile after enforcement, with its trigger ids. A casefile without synthesis returns an explicit "synthesis not run" status rather than a level.
- **Deviation, deliberate: `rerun_case` is confined to the configured output directory.** Rerun writes `memo.md` and `casefile.json` into the directory it is given. On the CLI a person types that path; over MCP a host supplies it, so an unconfined argument is a write primitive pointed anywhere the process can reach. `case_dir` is resolved (symlinks included) and refused outside `COLDSCREEN_OUTPUT_DIR`. The CLI is unchanged, so the two paths differ here on purpose; the alternative was matching the CLI and accepting the wider surface. Confining the directory turned out to be necessary and not sufficient, which the review caught; see the write-through-a-symlink entry below.
- **No resources, no HTTP.** Streamable HTTP, SSE, OAuth, and exposing case files as MCP resources were all out of scope in the work order and stay in FUTURE.md. The memo already returns in the tool result, so file resources buy little for a much wider surface.
- **Deviation, mechanical: the test module builds its asyncio event loop at import time.** pytest-socket's guard is installed in `pytest_runtest_setup`, and asyncio's Unix selector loop creates its self-pipe with `socketpair()`, which the guard blocks. Building the loop during collection, before the guard exists, lets the SDK's in-memory client run with `--disable-socket` fully on. The gate was not weakened: sockets stay blocked for the duration of every test, and one test asserts that a real `socket.socket()` still raises inside an in-memory MCP session. If that had not worked the instruction was to stop rather than relax the gate.

CI needed no change and got none: the test job installs `.[dev]`, which pulls in the `mcp` extra, so the MCP tests run on every supported Python version, and the wheel-install smoke job still installs the plain wheel, which keeps the extra-absent path exercised. One consequence to note rather than fix here: `pip-audit` runs over the plain wheel environment, so the `mcp` dependency tree is not audited. Auditing an extra is a CI decision beyond this sprint's scope.

Verified end to end outside pytest, without Ollama: `coldscreen mcp` spawned as a subprocess and driven with the SDK's stdio client listed both tools, returned the missing-key error as a clean tool error, re-rendered the golden case through `rerun_case`, and refused an out-of-directory `case_dir`. The re-rendered memo was byte-identical to the committed snapshot, and stdout carried nothing but JSON-RPC.

### 2026-08-19: MCP sprint reviewed; the write, not the directory, is what needed confining
An independent review of the MCP sprint was adjudicated against the primary documents. Two findings were accepted as must-fix, and the first is the interesting one.

**Writing through a symlink defeated the confinement.** `rerun_case` resolved `case_dir` and refused anything outside the output directory, then handed that directory to code which wrote `case_dir / "memo.md"` with an ordinary text write. A symbolic link at that name is followed, so replacing `memo.md` with a link to a file elsewhere on the machine let a confined directory produce an unconfined write. The reviewer demonstrated it end to end: the victim file outside the output directory was replaced with memo text. The mistake in the original design was thinking about the path as a string to be validated rather than as a name that is resolved again, by the kernel, at the moment of writing.

Fix: every tool-owned write now goes through `casedir.write_case_text`, which opens with `O_NOFOLLOW`, so the kernel refuses a symlink at the final name and there is no window between checking and writing. Where a group of files is written, the names are lstat-checked first as well, so a refusal cannot leave a half-updated case (a rerun that would have hit a link at `memo.md` no longer rewrites `casefile.json` first). The tool-owned directories, the case directory and `evidence/`, are refused if they have become links, which also stops `shutil.rmtree` on the overwrite path from following one. This covers both `run_rerun` and `write_case`, so `screen_company --overwrite`, `rerun_case`, and both CLI commands are all fixed by the same change; the CLI gets it as defense in depth even though a person typing a path is a weaker threat model. Regression tests: a `memo.md` symlink pointing outside the output directory fails the tool and leaves the victim file byte-identical, and the same for an `evidence` directory replaced by a link on the overwrite path. Residual, stated rather than hidden: this defends the file names, not a concurrent replacement of the case directory component itself between the confinement check and the write, which would need `openat` against a pinned directory descriptor. Documentation that claimed confinement now says what is actually confined.

**The exact-title-match notice never reached MCP hosts.** The pipeline produces a notice when a name tie is resolved by exact title match while other candidates existed, the CLI prints it to stderr, and the MCP payload dropped it. That is the same class of mistake as silently picking a candidate: the caller cannot see a choice that was made for it. `notices` is now on the MCP success payload, with a test that an exact title match against set-aside candidates returns it.

Accepted and fixed in the same pass: `deck_path` now gets the checks Typer gives `--deck` (exists, is a file, readable) instead of being passed straight through, and is deliberately not confined to the output directory because pitch decks do not live there, with the residual written into PRIVACY.md (a host that can name a local PDF causes that file's extractable text to be persisted into the case directory and returned in the memo); `OSError` from persistence is now a clean actionable message naming the directory and the operation, on both adapters, with no object reprs or tracebacks; the lazy MCP import catches `ModuleNotFoundError` and re-raises unless `mcp` itself is genuinely absent, so a typo in `mcp_server.py` can no longer masquerade as a missing extra; and the verification entry below is corrected on the SDK's `Requires-Python` (`>=3.10`, which is the SDK's floor and not this project's 3.11).

Declined, with the orchestrator's agreement: a declared output schema with a status discriminator for the tool results. The status field is documented in the tool descriptions and the payload shape is stable; a declared schema is a nicety, not a safety property, and this sprint's scope was fixed.

Nothing was relaxed to make the fixes fit: pytest-socket stays armed, the rubric was not touched, and no transport was added. The reviewer's own attack was reproduced against the fixed code as a test rather than trusted from the report, and the memo snapshots are still byte-identical, which is the useful proof that `O_NOFOLLOW` changed only where the bytes go and not what they are.

### 2026-08-19: charges list walk; official spec still has no query params
The official public-data charges list still documents path parameter `company_number` only. Filing history and officer appointments on the same spec site document `items_per_page` and `start_index`. The client now walks charges with `get_paginated`, `total_key=total_count`, and the same received-count advance as officers and filings. Each page is persisted as `charges_p1`, `charges_p2`, and so on. Config adds `max_pages_charges` (default 10, validated like the other page caps).

If a later page adds no new items, the walk stops. Unique items are kept by `charge_code` when present, otherwise by a conservative serialization of the item so two distinct charges are not dropped. REG-015 still fires when `total_count` exceeds the unique retrieved set, and now states retrieved N of M plus whether retrieval stopped at the page cap or because further pages did not advance. A first page that already covers `total_count`, or that carries no total, is one GET. 404-behind-a-link is unchanged: persist the 404, leave charges unset.

Live page-size maxima, whether the live endpoint honors those query fields, and live 429 headers remain UNVERIFIED. This sprint did not call the live API and did not try to trip the production rate limit. Offline tests cover Retry-After (recorded sleep, not a real wait) and backoff when the header is absent.

### 2026-08-19: hermetic TLS SNI pin; keep the httpx pool assignment fail-closed
The site pin still installs a custom httpcore `NetworkBackend` by assigning `pool._network_backend` after construction. The steps are `pool = getattr(self, "_pool", None)`, `isinstance(pool, httpcore.ConnectionPool)`, then that assignment. That is a private coupling.

Why it exists: installed `httpx.HTTPTransport.__init__` (httpx 0.28.1) has no `network_backend` parameter. Its parameters are `verify`, `cert`, `trust_env`, `http1`, `http2`, `limits`, `proxy`, `uds`, `local_address`, `retries`, and `socket_options`. It constructs `httpcore.ConnectionPool` internally and does not pass a backend in. Installed `httpcore.ConnectionPool.__init__` (httpcore 1.0.9) does accept `network_backend`, but that hook is not reachable through httpx's public constructor. Pinning has to live below Host and TLS SNI so those stay on the origin hostname (httpcore `start_tls` uses `server_hostname` from the origin host). pyproject lower bounds remain `httpx>=0.27` and `httpcore>=1.0`. There is no public hook in the installed httpx signature. This entry cites those signatures, not a GitHub issue.

Fail-closed: if `_pool` is missing or is not a `ConnectionPool`, constructing `_PinnedTransport` raises `RuntimeError` and the site stage refuses to run rather than fetching unpinned.

Chosen path: keep the private assignment, the isinstance guard, and the hermetic HTTP Host-header plus TLS SNI tests, until httpx grows a public hook. Then switch and delete the private assign.

A loopback HTTPS handshake now proves server-observed SNI. The test binds `127.0.0.1` only, uses a fictional hostname, a runtime openssl cert with `SAN DNS:hostname`, and client `verify=` against that cert (never `verify=False`). `_PinnedTransport` forwards constructor kwargs to `HTTPTransport` so the test can pass `verify=`. Production `_SiteFetcher` still constructs `_PinnedTransport(pinner)` and keeps default verify-on against system CAs.

Alternatives considered and rejected this sprint: dropping httpx for hand-rolled TLS (more surface), pinning an upper httpx bound with no public-API evidence (churn without a hook), adding a third-party TLS test extra (`cryptography` or `trustme`).
